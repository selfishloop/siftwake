# Küçük sayfanın maliyeti: dosya değişiklik denetimi

Önceki [normalleştirme adımındaki](CHANGED-RUNS-10K-20261015.md) tek-sonuç
gerilemesi incelendi. İki prototip ölçüldü ve **reddedildi**; runtime
değişiklikleri geri alındı. Önceki changed-runs normalizer korunur, default
aynı. Yeni aktif feature, Windows kütüphanesi veya kalıcı format yok.

Kalıcı kazanım bu turda hız iddiası değildir: küçük sayfa için daha yoğun
ölçüm, ayrı guard sayaçları ve ek doğruluk kontrolleridir. Eski +%66,89
gerilemenin tam nedeni çözülmüş sayılmaz; o p95 artışı açık kalır.

## Ölçüm kapsamı

Mevcut `data/rkyv-corpus-20261009/json.payload-bench` dosyasının aynı ilk10k
belgesi;264.842.858 B gövde.100k corpus header'ı koşu büyüklüğü değildir.
Sabit `data/benchmark-work/fdb` yeniden kullanıldı; yeni corpus/DB kopyası,
ingest/reset veya disk taşıması yok. SQLite bu turda yeniden ölçülmedi.

Her prototip değişiklikten önce dondurulmuş aynı kontrol reader'a karşı
ölçüldü; aynı harness, release/experimental-builder-budget, record-read,
diagnostic kapalı. İkinci çift ters sırada; seed ile karışık query/get sırası.
Sıcak OS cache, eviction yok. Total, tam belge, version ve sıralama oracle'ı
geçti. Oracle resident olduğundan bu reader'ların RAM'i motor RAM'i değildir.

İki ayrı iş yükü var; sonuçları birbirinin yerine kullanmıyoruz:

- `--matrix <seed> --pages-only`:8 sayfa,200 sample/senaryo/proses,
  üç çiftte600 pooled sample. Aynı rastgele get kontrolü de200 round çalışır.
- Normal matrix:30 temel sorgu +8 sayfa; temel sorguda20 sample/proses
  (60 pooled), sayfada5 (15 pooled). Nearest-rank p95.

Yeni `--pages-only` anahtarı ve `measure-window-matrix.ps1 -PagesOnly`
yalnız benchmark aracındadır. Normal matrix örnek sayıları değişmedi.
Profil loglarına `limit` eklendi; aynı text/offset'in farklı sayfaları artık
doğrudan ayrılır.

## Reddedilen iki prototip

İlk prototip: mevcut full-filter kanıtı bütün slotların canlı/görünür olduğunu
kanıtlıyorsa, sınırlı ID önekini posting okuma/kesiştirme yapmadan üretmek.
Silinmiş/gizlenmiş kayıt varsa eski yol; text source izinleri ve boş-text için
source/index guard korunur. Yeni cache veya payload biçimi yoktu.

İkinci prototip: Windows'ta source uzunluğu/last-write-time kontrolünü
`GetFileAttributesExW` ile yapmak; bağlantı, dizin, desteklenmeyen yol ve API
hatasında mevcut metadata yolu. Microsoft API'si bağlantının kendi bilgilerini
döndürdüğü için takip eden eski yol korunmuştu.
[API sözleşmesi](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfileattributesexw),
[dönen boyut/zaman alanları](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/ns-fileapi-win32_file_attribute_data).

| Prototip / iş yükü | `the` /offset0 /limit1 kontrol p95 | Aday p95 | Değişim | Hızlı çift | Bütün senaryolar düşük/yüksek |

Posting kısayolunun geniş matrix sonucu yoğun sayfa iş yükünde doğrulanmadı.
Windows varyantı hedef senaryoda iki iş yükünün pooled p95'inde de yüksek;
güvenilir hız kazancı sağlamadı. İkisi de reddedildi. Kısayolun hiç
kullanılmadığı uzun olumsuz sorgulardaki farklar o kısayolun kazancı diye
yorumlanmaz; ortam/derleme/cache etkilerinin tümü ayrıştırılmadı.

## Asıl sabit maliyetin ölçümü

`page-guard-profile-20261015`: posting prototipi kaldırıldıktan sonra mevcut
standart metadata yolu. Release/builder-budget/diagnostic-timing/record-read,
aynı10k;3 proses ×3 warm iteration. Önce proses içi, sonra prosesler arası
medyan. Sıcak OS cache/eviction yok. Bunlar instrumented wall span'lerdir;
CPU attribution veya normal API p95 değildir. İç içe span'ler toplanmaz.
[Sayaçlar ve her proses](benchmarks/page-guard-profile-20261015-summary.json).

`the`, offset0, limit1:

| Span | Medyan | Çağrı |
|---|---:|---:|
| Sorgu toplamı |0,3466 ms |1 |
| Filter/visibility/text (iç içe) |0,3260 ms |1 |
| Source/index guard (iç içe) |0,2778 ms |5 |
| Source path metadata (guard'ın içinde) |0,2478 ms |5 |
| Index handle metadata (guard'ın içinde) |0,0267 ms |5 |
| Posting intersection |0,0004 ms |5 |
| Sayfa birleştirme/belge okuma |0,0203 ms |1 |
| Gövde normalleştirme/tarama |0 |0 |

Guard/sorgu medyan oranı yaklaşık%80; üç prosesin guard medyanları
0,2778/0,2534/0,3354ms. Küçük sayfada posting kesişimi veya gövde fold'u
baskın değil.50 sonuçta toplam1,0818ms/guard0,3313ms;200 sonuçta toplam
6,3344ms/guard0,5402ms ve sayfa hydrate5,5796ms. Limit büyüdükçe belge
getirme maliyeti önem kazanıyor. Uzun olumsuz `the zx`te toplam283,1944ms,
guard0,9383ms/gövde fold94,2336ms: küçük sayfanın teşhisi uzun taramaya
genellenmez. Bu profiller önceki +%66,89 farkın nedensel açıklaması değildir.

Sonraki yön: Windows'ta değişmez source/index dosyalarının ömrü ve sahipliği
üzerinden bu path kontrolünün tekrarını azaltmak. Dosya değişimini gözden
kaçıran bir guard cache'i kullanılmayacak; replace/delete/aynı-boyutta
bozulma, eski fixture ve kurtarma davranışı korunmalı. Bu tasarım henüz
uygulanmadı; performans kazancı iddiası yok.

## RAM, disk ve açık işler

Bu turda RAM/working-set veya yazma/bakım ölçülmedi. Önceki9,18MiB indexing
private/13,21MiB WS geçmiş ölçümdür; query tepe belleği değildir. Yeni RAM
iyileşmesi veya sıfır gerileme iddiası yok. Kaynak/index/WAL/manifest biçimleri
aynı;0.1 fixture korunur. Her iki prototipin dört read-only batch'inde
FDB/cache/SQLite dosya boyutu ve hash'leri değişmedi.

## Son doğrulama

İki runtime prototipi kaldırıldıktan sonra default, builder-budget ve
all-features all-targets suite'leri geçti. Kesilme/tek-bayt bozulma/bozuk
source + sağlam cache/process kill/merge kill/interop kontrolleri başarılı.
Ek tam-filtre testi exact/range/link/text, küçük sayfa, gizlenen sürüm,
tombstone, update/flush/reopen sonuçlarının tam belge/version eşitliğini
kontrol eder. Warm arama sonrası bozulma testi source yanında index'i de
kapsar.0.1 fixture'ın Git durumu boş.

Default ve all-features `cargo clippy --all-targets -- -D warnings`,
`cargo fmt --check` ve `git diff --check` geçti. Loglar:
`page-guard-final-tests-{feature,all,default}-20261015.log`,
`page-guard-final-clippy-{all,default}-20261015.log`,
`page-guard-final-fmt-20261015.log`.

Normal release examples yeniden build edildi; diagnostic kapalı. Son38-case
total/tam sayfa/version kontrolü geçti (`page-guard-final-matrix-check-20261015.jsonl`).
Son reader'ın `.text` bölümü deney öncesi kontrol reader'ıyla byte düzeyinde
aynı; bütün executable dosyasının aynı olduğu iddia edilmez.
[Son artifact'lar ve test durumu](benchmarks/page-guard-final-artifacts-20261015.json).
