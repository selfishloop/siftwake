# Kaynak doğrulamasında tek frame tamponu

**Karar: reddedildi, runtime kodu geri alındı.** İlk dinamik reuse RAM'de,
header-plan varyantı sıcak okumada kabul kapısını geçmedi. Bu belge deneyin
tarihçesidir; motorun güncel allocation davranışını anlatmaz.

## Kapsam ve güvence

Native deferred/record-read doğrulamasında önce küçük TXN2 header'larından
en büyük frame uzunluğu belirlenir; kaynak başına bir tampon ayrılır. Gövdeler
bu aşamada okunmaz. Sonra mevcut replay bütün header/body/footer CRC, tam
kaynak CRC, sequence/checkpoint/bounds ve borrowed belge/manifest kontrollerini
yapar. CRC ve callback yalnız actual frame length slice'ını kullanır;
büyük→küçük→büyük→boş frame'larda kalan baytlar hesaba katılmaz.

Plan header CRC/magic ve64 MiB MAX_FRAME sınırını kontrol eder; kaynak
planlama ile replay arasında büyürse yeniden allocation yerine hata verir.
Gövde bir kez okunur; header başına fazladan küçük read/seek vardır. Tampon
source kontrolü bitince bırakılır; bütün kaynaklar aynı anda RAM'e alınmaz.
Strict owned replay'in allocation/drop davranışı ve streaming-open aynı kalır.
Yeni feature, kalıcı/cache formatı, corpus/DB/reset/prepare yok.0.1 korunur.

## İlk prototip reddedildi

Önce frame tamponunun high-water kapasitesi büyütülerek reuse denendi.
`benchmarks/frame-buffer-reads-10k-20261013-*` beş çiftte ilk search hızlı
olsa da gözlenen proses tepe working set~29,87→37,89 MiB arttı. Gözlenen
private peak medyanı~27,01→35,03 MiB. Bu hali **reddedildi**; dinamik büyüme
yolunun yerine header'dan önceden boyutlandırma uygulandı. Warm sonuçlar
bu ilk prototipten final tasarımın sonucu olarak aktarılmaz.

Ön prototip tek diagnostic gözleminde first search195,93→161,23 ms,
source verify168,96→147,81 ms, read+allocate78,14→67,32 ms. Bu profil
final pre-plan sürümünün ölçümü değildir; nested wall-time span'lar toplanmaz.

## Ölçüm sözleşmesi

Mevcut aynı ilk10k belge `data/rkyv-corpus-20261009/json.payload-bench`:
264.842.858 text byte,2.057–51.197 byte/doc, sekiz Gutenberg kitabının
benzersiz/örtüşen pasajları. Sabit mevcut FDB slotu,sequence20,5 source,
delta0. Control önceki IEEE hızlandırılmış sürüm; iki taraf release,
merge-postings+delta-bitmaps, diagnostic kapalı. OS cache sıcak, eviction yok.

`tools/measure-borrowed-source.ps1 -Prefix docs/benchmarks/frame-plan-reads-10k-20261013
-Control output/frame-buffer-control-20261013.exe -CheckMatrix -MeasureMemory`:
beş dönüşümlü fresh-process open→get9999→ilk quixote→repeat pair. Get sonrası
iki tarafta pending5,search sonrası0; first quixote56 total/50 hit/version20
kontrolü. Üçer warm process, motor başına9k timed get ve query başına90 sample:
the/quixote/he/the man full total/page/StoredDocument version bağımsız corpus
oracle'ına eşit olmalı. Nearest-rank pooled p95/p99; query p99 maksimum sample.
Oracle/warmup API timer dışı.38-case tek full-oracle correctness, tekrarlı
38-query performans ölçümü değildir. DB/cache byte ve SHA256 önce/sonra aynı
olmalı. SQLite/strict open/yazma/bakım/cold cache/concurrent yük ölçülmez.

Bellek first-use prosesinin open/get/search/repeat penceresinde hedef10 ms
poll ile Windows PrivateMemorySize64 ve PeakWorkingSet64 üzerinden örneklenir.
Private committed bellek, working set resident proses sayacıdır; motor
allocation sayacı değildir. Son örnekler arasında kısa peak'ler kaçabilir;
exact peak veya bütün workload RAM kapısı sayılmaz. Ham sample sayıları ve
observed byte sonuçları `.jsonl.memory.json` dosyalarında tutulur.

## Final header-plan sonucu: reddedildi

Beş çiftte medyan ilk search192,72→148,58 ms (%22,91), open+get+search259,51
→214,72 ms. Gözlenen tepe WS medyanı31.322.112→31.346.688 B (+24.576 B),
private peak28.332.032→28.336.128 B (+4.096 B): önceki~8 MiB artış giderildi.

Ancak üçer warm process'in pooled p95 değerleri: get0,0555→0,0625 ms,
the224,45→254,55 ms,quixote6,53→7,79 ms,he225,89→253,66 ms,
AND232,02→267,94 ms. Her beş işlemin per-process p95'i3/3 eşleşmede arttı;
warm search artışı~%12–19. Query algoritması değiştirilmemiş olsa da bunu
ölçüm gürültüsü diye göz ardı etmedik; sebebi kesinleştirilmedi. Genel kapı
geçmedi, kaynak tampon planlama/reuse değişiklikleri geri alındı. Yeni çok-frame
testi ve read-only bellek ölçüm aracı korundu.38-case correctness ve DB hash
eşitliği geçti; final kaynak kodu önceki frame allocation yoluna geri döndü.

Ham/log/summary: `benchmarks/frame-plan-reads-10k-20261013-*`.

all-features suite de geçti; final plan streaming-open yolunu değiştirmez.
