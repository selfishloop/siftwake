# IEEE checksum hızlandırması: mevcut 10k DB

## Kapsam

`format::crc_extend`128 byte ve üzeri girdide pinned `crc32fast=1.5.0`
kullanır; küçük başlıklarda mevcut slicing-by-8 tabloları kalır. Aynı IEEE
CRC32 polinomu, initial/final complement ve streaming-state sözleşmesi
korunur. Hasher finalized state alıp verdiğinden wrapper iki yönde complement
yapar; `crc_combine` değişmez. CRC32C'ye geçilmez. Bu genel checksum
kütüphanesidir; hazır DB/arama motoru eklenmez.

Kaynak/WAL/index/cache formatı, CRC alanları ve bütün doğrulama adımları aynı.
Yeni feature yok. Bu aritmetik optimizasyon strict/default dahil ortak checksum
yolundadır; record-read/deferred API opt-in kararı değişmez. ARM/x86 CPU
seçimi kütüphanenin runtime dispatch'ine bırakılır; destek yoksa software
fallback vardır. [Kütüphane resmi açıklaması](https://docs.rs/crc32fast/latest/crc32fast/).
Bu rapor pinned1.5.0'ı ölçer; latest sayfadaki sonraki sürümler ölçülmüş sayılmaz.

## Profil

Diagnostic release tek paired gözlemde ilk quixote search339,44→185,87 ms,
source verification307,37→172,27 ms. Kaynak frame CRC138,06→20,83 ms;
borrowed validation57,82→58,00 ms, frame read+allocate93,37→81,04 ms.
Index block checks25,09→8,77 ms; page hydration12,70→5,74 ms. Nested spans
toplanmaz; bunlar wall-time, CPU attribution değil. Profil nihai tekrar
ölçümünün yerine geçmez. Ham dosyalar `benchmarks/crc-profile-{before,after}.jsonl`.

## Ölçüm sözleşmesi

Mevcut `data/rkyv-corpus-20261009/json.payload-bench` aynı ilk10.000 belge:
264.842.858 text byte,2.057–51.197 byte/doc, sekiz Gutenberg kitabının
benzersiz/örtüşen pasajları. Yeni corpus indirme/üretme yok. Sabit mevcut
`data/benchmark-work/fdb`:10k doc,sequence20,5 immutable source,delta0.
Reset/rebuild/prepare yok; DB/cache dosyalarının byte/SHA256 değerleri önce/sonra
kontrol edilir. Ryzen7 7840HS,Windows,rustc1.99.0; farklı işlemci/fallback
performansı ölçülmez. Control bir önceki borrowed doğrulama executable'ıdır;
iki taraf release +merge-postings +delta-bitmaps, diagnostic kapalı.

Runner `tools/measure-borrowed-source.ps1 -Prefix docs/benchmarks/crc-reads-10k-20261013
-Control output/crc-read-control-20261013.exe -MeasureStrict -CheckMatrix`.
Beş dönüşümlü fresh-process pair: record-read open→get9999→ilk quixote search
→repeat. İki tarafta get sonrası pending5,search sonrası0; kaynak doğrulaması
timer içindedir. İlk probe56 total/50 hit/version20 kontrolüdür; bağımsız full
corpus oracle değildir. Ayrıca beş strict open pair tam kaynak/index CRC ve
replay yapar. Strict /record-read iş miktarları eşit sayılmaz.

Üçer warm process: the/quixote/he/the man,30 timed round/query/process,
100 get key ×30 round/process; bütün toplam ve sıralı50 StoredDocument/version
bağımsız corpus oracle'ına eşit olmalı. Motor başına9k timed get,query başına90
sample; nearest-rank pooled p95/p99,query p99 burada maksimum örnektir.
Untimed full warmup ve oracle hazırlığı timer dışıdır. OS cache sıcak; eviction
yok. Matrix-check38 query/page için birer full-oracle correctness çalıştırır;
tekrarlı38-query performans/regresyon kapısı değildir. Full integrity ayrı.

SQLite yeniden ölçülmez; bu FDB aritmetik değişikliğinin paired ölçümüdür.
RAM/working-set, yazma/bakım, concurrent/cold cache,50k/100k ölçülmez.
DB disk alanı ile executable/dependency disk alanı birbirine karıştırılmaz.

de geçti; bu bounded unit byte array yeni belge corpus'u değildir.
