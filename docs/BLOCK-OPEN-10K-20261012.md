# VFY01 ile indeks blok kontrolü

## Kapsam ve biçim

Bu adım `open_deferred` altında yalnız indeks CRC maliyetini küçültür.
Kaynakların ilk kullanımda segment düzeyinde tam kontrolü korunur.
Default `open`/`open_with_options`, kaynak/SEG04/OFF1 biçimleri ve0.1 fixture
değişmedi. SQLite benzeri per-record source erişimi henüz uygulanmadı.

`prepare_open_checks()` explicit tam integrity kontrolünden sonra aktif
immutable indekslerin her256 KiB bloğunun IEEE CRC32'sini `.vfy` dosyasına
yazar. Belge veya posting kopyası yok; tam veri taraması hazırlama maliyetidir,
open ölçümünden ayrı kaydedilir. Cache invalidation/fallback correctness için
metadata version ve bütünlük kontrolleri şarttır.

VFY01 ayrı sürümlü **türetilmiş cache**:

| Byte | İçerik |
|---|---|
| 0..8 | FDBVFY01 magic |
| 8..16 | SEG04 checksum prefix byte uzunluğu; footer hariç |
| 16..24 | Sabit block byte uzunluğu262144 |
| 24..28 | SEG04 footer'daki beklenen prefix CRC |
| 28..32 | Block sayısı |
| 32..son4 | Her block için little-endian u32 CRC |
| son4 | Önceki bütün cache byte'larının CRC32'si |

Loader16 MiB cache sınırı, exact length/count, sürüm/binding ve table CRC
kontrolü yapar. Block CRC'leri gerçek block uzunluklarıyla birleştirilir;
ortaya çıkan root, mevcut SEG04 footer checksum'una eşit olmalıdır.
SEG04 footer CRC ve source end/checksum binding de normal kontrollerden geçer.

Deferred open header ve directory'nin dokunduğu block'ları gerçek index
byte'larından CRC ile doğrular; directory grammar/offset/key/version/posting
bounds kontrolü aynıdır. Sonra positional payload/posting read'lerinin
dokunduğu block'lar kontrol edilir. Başarılı block'lar oturum içinde bir kez
işaretlenir. Touched block checksum'u başarısızsa veri döndürülmez. Sonraki
dış dosya değişikliği desteklenmez; explicit full integrity yeniden tarar.

VFY eksik, kesik, stale veya bozuksa tam index CRC yolu kullanılır. Kontrol
edilen directory/header block'u bozuksa geçerli kaynaktan normal rebuild yolu
çalışabilir; lazy unopened payload block'u bozuksa erişimde hata döndürülür.
Sağlam VFY/index kaynağın kontrolünü atlatamaz; get/search/write/bakım guard'ları
aynıdır. Cache hazırlanırken tam index root kontrol edilmeden yayın yapılmaz;
temporary write/sync/rename kullanılır. Crash sonrası cache yok/kesik olursa
authoritative source doğrulaması ve mevcut tam CRC fallback'ı korunur.

## Doğrulama

Testler table'ın her kesimini ve her tek-byte bozulmasını, repaired table CRC
ama wrong root'u, stale length binding'i, block sınırını aşan read'i ve henüz
kontrol edilmeyen block'taki corrupt/cut veriyi kapsar. Publication öncesi child
process kill eski checksum cache'ini korur. Test-only staging hook runtime
derlemesinde yoktur. Default ve all-features native testleri7/7 geçti.

API compatibility: VFY hazırlanması `.fdb/.idx` byte'larını değiştirmiyor;
VFY yok/bozuk/sağlam durumlarında eski SEG04 yolu aynı belgeyi okuyor. Bozuk
source + sağlam VFY/index veri döndüremiyor.700 KiB tek bounded unit fixture'da
open'da dokunulmayan payload block'u get'te CRC ile reddediliyor; strict okuyucu
geçerli source'dan index'i yeniden oluşturabiliyor. Bu unit fixture benchmark
corpus'u değildir, test bitince temizlenir.0.1 fixture değiştirilmedi.

## Benchmark yöntemi

Mevcut aynı10k belge,5 segment,seq20,boş delta; source267.900.709 B ve
index353.242.581 B. Metin264.842.858 B,2.057–51.197 B/belge;8 Gutenberg
eserinden benzersiz/kısmen örtüşen pasajlar. Yeni corpus/DB yok; sabit FDB slotu
kullanılır. Yalnız küçük aktif VFY cache dosyaları eklenir; eski nesil cache'i
veya DB kopyası oluşturulmaz. SQLite tekrar ölçülmez.

Eski segment-deferred frozen exe ve yeni block-deferred exe aynı feature'lar:
experimental-merge-postings + experimental-delta-bitmaps, release thin-LTO,
diagnostic kapalı. Beş open çifti, order dönüşümlü; motor başına bir untimed
open. Üç ilk-get/ilk-quixote/tekrar-search probe çifti ve üç warm read çifti.
Warm read her süreç3.000 get /4 query ×30 timed tekrar, independent source
oracle ile total/ordered full StoredDocument/version kontrolü. Her query/key
untimed warmup; OS cache eviction yok. Bu dört query geniş38-senaryo kabulü
değildir. Cache/root hazırlama ve oracle süre dışındadır; source CRC ve lazy
block maliyeti API timer'larının içindedir. Nested profiler span'leri toplanmaz.

İlk source kontrolünün maliyeti korunur; yalnız open süresinden bütün ilk-use
workload hızlandı sonucu çıkarılmaz. Process RAM, concurrent yük, write/merge
hızı, cold OS cache ve50k/100k ölçülmez. Open/check/get timers farklı doğrulama
aşamalarını kapsar; SQLite~9 ms bağlantıyla aynı işi tamamlamış sayılmaz.

Runner `tools/measure-block-open.ps1`; veri üretmez/reset yapmaz, mevcut raporu
ezmez. Ham prefix `docs/benchmarks/block-open-10k-20261012`; executable SHA256,
preparation, VFY boyutları ve persistent source/index/ready hash'leri kaydedilir.
`output/open-read-control.exe` ile VFY öncesi gerçek frozen okuyucu compatibility
kontrolü de yapılır. Tam integrity ayrıca ölçülür.

### Hazırlama / disk / uyumluluk

Explicit checksum cache hazırlama API'si1.021,84 ms (tek örnek, warm cache);
öncesindeki normal full open ayrıca ölçülmüş, bu süreye dahil değil.
Hazırlama bütün integrity kontrolü + index CRC table taraması + write/sync
 içerir. Bir fresh VFY open sonrası explicit full integrity717,51 ms, pending0.

Yalnız aktif5 indeks için **5.580 B** ek derived metadata yazıldı. Corpus,
`.fdb/.idx/.ready` dosyalarının boyut veSHA256 değerleri aynı. Eski VFY öncesi
frozen executable SEG04 DB'yi başarıyla açtı;~905,74 ms açılışı yeni strict
performans karşılaştırması değil, compatibility kontrolüdür.0.1 fixture
bytes değişmedi; default/all-features testlerinde fixture okuma geçti.

Default/all-features all-targets testleri, ek native7/7 testleri,
`cargo fmt --check`, default veall-features `cargo clippy --all-targets -- -D warnings`
geçti. Publication öncesi process-kill ve VFY every-cut/every-byte testleri
ayrıca geçti. Ek test hazırlığından sonra VFY kaynak/metadata byte'larını
 değiştirmediğine dair native compatibility testleri de iki feature modunda geçti.

### Karar

Block CRC cache isteğe bağlı explicit preparation + deferred open altında
kullanılır. Default strict yol aynı kalır; VFY yoksa/eskiyse tam CRC fallback
korunur. Bu10k/sıcak cache ilk kullanım için ölçülmüş iyileştirmedir; SQLite
9 ms seviyesine erişilmedi, RAM ölçülmedi. Source'u kayıt/sayfa adresiyle
kontrol etme, binary/streamed directory başlangıcı ve38 query regresyonları
 sonraki adaylardır. Güncel yazma/bakım, RAM/disk ve concurrent workload işleri
[OPEN-WORK](OPEN-WORK.md) içinde açık kalır.
